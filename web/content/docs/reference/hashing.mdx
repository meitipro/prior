A seal is the sha256 of your text, a salt and your address, so the chain can date a description without seeing it. The contract and the browser compute the same bytes, and both are held to the vectors below.

## The bytes

The digest runs over the UTF-8 bytes of `text`, a bar, `salt`, a bar and the lower-case address with `0x`. The text is exactly as written: no trimming, no line-ending changes. The salt carries no bar, and neither does the address, so the join is unambiguous however many bars the text holds.

```python title="contracts/prior.py"
def seal_hash(text: str, salt: str, address: str) -> str:
    """
    sha256 over the UTF-8 bytes of text, salt and the lower-case address with
    0x, joined with a bar. The salt carries no bar and the address carries
    none, so the join is unambiguous however many bars the text holds. The
    site computes the same bytes, held to tests/vectors.json.
    """
    return hashlib.sha256((text + "|" + salt + "|" + address.lower()).encode("utf-8")).hexdigest()
```

The same in JavaScript, which is the code the site runs:

```js title="web/examples/seal-a-text.mjs"

import { sealOf } from '../lib/seal.mjs';

const seal = sealOf('A weekly newsletter on votes.', 's1', '0x3e8b3e8b3e8b3e8b3e8b3e8b3e8b3e8b3e8b41aa');
console.log(seal);
```
